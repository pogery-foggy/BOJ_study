# 구현 핵심

## 1. 한 문장 기억

문장의 조건을 상태·인덱스·전환 규칙으로 정확히 번역하고, 반복되는 판정은 작은 함수로 분리한다.

## 2. 언제 꺼내는가

- 특별한 알고리즘보다 조건 누락 없는 코딩이 핵심이다.
- 격자·배열·문자열을 문제의 규칙 그대로 변환하거나 센다.
- 예외, 동률, 방향, 재사용 여부가 정답을 가른다.

## 3. 핵심 상태 / 불변식

- 각 변수는 한 의미만 가진다. 예: `used[i]`는 해당 칸에 구조물을 이미 놓았는가.
- 한 줄/한 행을 검사하는 함수는 외부 상태를 오염시키지 않고 true/false를 반환한다.
- 문제의 조건 검사 순서를 코드의 분기 순서와 맞춘다.
- 같은 자원을 합쳐 쓸 수 있으면 빈도 배열에서 먼저 통합한 뒤 최대값을 구한다.

## 내 코드 스타일 C++ 최소 구현 골격

스타일 근거: [1475.cpp](./1475.cpp)의 전역 문자열과 고정 빈도 배열, `init()`/`solve()` 분리, 범위 `for`로 센 뒤 특수한 두 상태를 합치고 삼항식으로 최댓값을 갱신하는 구조를 축약했다.

```cpp
string N;
int arr[10], maxed = -1;

void init() { cin >> N; }

void solve() {
    for (auto a : N)
        arr[a - '0']++;

    arr[6] += arr[9] + 1;
    arr[6] /= 2;
    for (int i = 0; i < 9; i++)
        maxed = maxed > arr[i] ? maxed : arr[i];
}
```

큰 격자 조건 구현도 [14890.cpp](./14890.cpp)처럼 전역 `map`/`is_used`, 명시적인 중첩 `for`, `flag`/`cnt` 상태를 사용한다. 현재 골격의 목적은 문제 문장의 예외 규칙을 먼저 빈도·상태 갱신 순서로 번역하는 사용자 습관을 보여 주는 것이다.

## 5. 빈 화면 구현 순서

1. 입력·출력과 제약을 자료형으로 옮긴다.
2. 상태 변수마다 뜻을 주석 한 줄로 정한다.
3. 문제 조건을 번호 순서대로 작은 판정으로 나눈다.
4. 행/열처럼 같은 로직은 1차원 함수 하나로 통일한다.
5. 상태 갱신은 모든 검사가 통과한 뒤 수행한다.
6. 경계, 동률, 재사용, 합쳐 쓰는 자원을 집중 검사한다.

## 6. 자주 틀리는 지점

- 행과 열 코드를 복사해 인덱스 하나만 잘못 바꾸는 실수.
- 조건을 검사하다 실패했는데 일부 `used` 상태는 이미 바뀐 채 남는 실수.
- 6과 9처럼 공유 가능한 자원을 합친 뒤 올림 나눗셈하지 않는 실수.
- 출력용 디버그 문장을 남기는 실수.
