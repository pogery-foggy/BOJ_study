# 그리디 핵심

## 1. 한 문장 기억

지금의 선택이 미래 선택지를 가장 덜 해친다는 교환 논리를 세운 뒤, 그 기준으로 매번 하나를 확정한다.

## 2. 언제 꺼내는가

- 선택을 되돌리지 않아도 최적해가 되는 국소 기준을 증명할 수 있다.
- 정렬 후 앞에서부터 고르거나, 매번 최소/최대를 우선순위 큐에서 꺼낸다.
- 첫 특정 사건 이후 남은 모든 선택의 부호·행동이 한 방향으로 고정된다.

## 3. 핵심 상태 / 불변식

- 지금까지 고른 해는 어떤 최적해의 앞부분으로 교체해도 손해가 없다.
- 회의 선택에서는 마지막 종료 시각 이전 선택이 최대로 유지된다.
- 최적 병합에서는 가장 작은 두 묶음을 먼저 합쳐도 최적해가 존재한다.
- 식 최소화에서는 첫 `-` 이후의 모든 수를 빼는 것이 가능한 괄호 배치와 같다.

## 4. C++ 최소 구현 골격

```cpp
// 종료 시간이 빠른 활동부터 선택
sort(job.begin(), job.end(), [](auto a, auto b) {
    if (a.second != b.second) return a.second < b.second;
    return a.first < b.first;
});

int count = 0, lastEnd = INT_MIN;
for (auto [start, end] : job) {
    if (start >= lastEnd) {
        ++count;
        lastEnd = end;
    }
}

// 최적 병합
priority_queue<long long, vector<long long>, greater<long long>> pq;
long long cost = 0;
while (pq.size() > 1) {
    long long x = pq.top(); pq.pop();
    long long y = pq.top(); pq.pop();
    cost += x + y;
    pq.push(x + y);
}
```

## 5. 빈 화면 구현 순서

1. 한 선택이 미래에 남기는 자유도를 정의한다.
2. 후보 기준(빠른 종료, 작은 비용 등)을 세운다.
3. 다른 선택을 그 기준의 선택으로 바꿔도 나빠지지 않는지 교환해 본다.
4. 정렬 또는 우선순위 큐를 준비한다.
5. 선택 가능 조건과 선택 후 상태 갱신을 쓴다.
6. 같은 키, 원소 1개, 선택 불가능한 후보로 검산한다.

## 6. 자주 틀리는 지점

- 그럴듯한 국소 선택을 증명 없이 사용하는 실수.
- 시작 시간이 빠른 회의를 고르는 등 미래 공간을 더 많이 막는 기준을 택하는 실수.
- 합산 비용을 `int`에 저장해 overflow하는 실수.
- 동률 정렬 기준이 선택 가능성에 영향을 주는데 생략하는 실수.
