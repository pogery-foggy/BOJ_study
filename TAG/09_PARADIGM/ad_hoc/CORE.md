# 애드혹 핵심

## 1. 한 문장 기억

유명 알고리즘을 억지로 찾기보다 작은 사례를 직접 전개해 답을 가르는 문제 고유의 규칙을 증명한다.

## 2. 언제 꺼내는가

- 표준 자료구조나 전형 알고리즘보다 관찰 하나가 풀이 전체를 결정한다.
- 작은 값의 결과가 몇 구간으로 나뉘거나 빠르게 안정된다.
- 복잡해 보이는 생성 과정을 실제로 모두 만들 필요 없이 답의 범주만 판별할 수 있다.

## 3. 핵심 상태 / 불변식

- 관찰한 패턴은 예시 몇 개가 아니라 입력 전체 범위를 덮는 근거가 있어야 한다.
- 답이 바뀌는 경계값을 명시하고 각 구간이 빠짐없이, 겹치지 않게 나뉜다.
- 구현은 증명에서 얻은 분기만 남기고 불필요한 시뮬레이션을 제거한다.

## 내 코드 스타일 C++ 최소 구현 골격

스타일 근거: [28292.cpp](./28292.cpp)의 전역 `N`, 작은 사례를 주석으로 먼저 전개한 뒤 `init()`과 세 구간의 짧은 `solve()`로 끝내는 구조를 그대로 축약했다. 이 폴더의 실제 풀이를 그대로 기준으로 삼았다.

```cpp
/*
작은 N의 결과를 직접 적어서 답이 바뀌는 경계를 찾는다.
*/
int N;

void init() { cin >> N; }

void solve() {
    if (N < 3)
        cout << 1;
    else if (N < 6)
        cout << 2;
    else
        cout << 3;
}
```

숫자와 경계는 문제마다 다시 증명해야 하지만, 관찰 결과를 불필요한 자료구조 없이 곧바로 `if`/`else if`로 옮기는 것이 이 코드에서 확인되는 구현 습관이다.

## 5. 빈 화면 구현 순서

1. 가장 작은 입력부터 충분히 직접 계산한다.
2. 값이 바뀌는 지점과 변하지 않는 양을 찾는다.
3. 그 현상이 계속되는 이유를 문장으로 증명한다.
4. 답이 달라지는 최소 경계를 정확히 적는다.
5. 증명에 필요한 분기만 코드로 옮긴다.
6. 각 경계의 바로 전·경계·바로 다음 값을 검사한다.

## 6. 자주 틀리는 지점

- 표본 몇 개만 보고 패턴이 영원히 유지된다고 추측하는 실수.
- `<=`와 `<`가 경계에서 뒤집히는 실수.
- 문제의 작은 예외를 일반식에 억지로 포함시키는 실수.
- 짧은 코드라는 이유로 관찰의 증명을 생략하는 실수.
