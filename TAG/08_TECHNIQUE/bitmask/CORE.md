# 비트마스크 핵심

## 1. 한 문장 기억

작은 집합의 포함 여부를 정수의 각 비트 하나에 대응시키면 검사·추가·삭제·토글을 O(1)에 할 수 있다.

## 2. 언제 꺼내는가

- 원소 수가 대략 20~60개이고 부분집합 또는 방문 상태를 통째로 저장한다.
- 여러 bool 상태를 하나의 정수로 압축한다.
- 완전이진트리 인덱스처럼 2진 표현 자체가 부모·자식 관계를 나타낸다.

## 3. 핵심 상태 / 불변식

- 원소 x를 0번 비트부터 쓰려면 입력 직후 `--x`한다.
- x가 포함됨은 `(mask & (1ULL<<x)) != 0`과 같다.
- 부모 인덱스는 `x>>1`; 비트를 하나 버릴 때마다 한 층 위로 간다.

## 내 코드 스타일 C++ 최소 구현 골격

스타일 근거: [11723.cpp](./11723.cpp)의 전역 `cmd, s, x, N`, 명령마다 입력을 이어 받는 `solve()`, `if`/`else if` 분기와 직접 쓴 비트 연산을 축약했다. 원본에 없는 람다와 `uint64_t` 헬퍼는 넣지 않았다.

```cpp
string cmd;
int s, x, N = 20;

void init() { cin >> cmd; }

void solve() {
    if (cmd == "add") {
        cin >> x;
        x--;
        s = (s | (1 << x));
    } else if (cmd == "remove") {
        cin >> x;
        x--;
        s = (s & ~(1 << x));
    } else if (cmd == "check") {
        cin >> x;
        x--;
        int check = (s & (1 << x));
        cout << (check ? 1 : 0) << '\n';
    } else if (cmd == "toggle") {
        cin >> x;
        x--;
        s = (s ^ (1 << x));
    } else if (cmd == "all")
        s = (1 << N) - 1;
    else
        s = 0;
}
```

`main()`에서는 원본처럼 `T`를 읽고 `for (int testcase = 0; testcase < T; testcase++)`마다 `init(); solve();`를 호출한다. 31번 이상 비트를 쓸 때만 `1LL << x`와 `long long`으로 함께 넓힌다.

## 5. 빈 화면 구현 순서

1. 각 비트가 뜻하는 원소와 0/1 기반 인덱스를 정한다.
2. 필요한 정수 폭(`int`, `long long`, `uint64_t`)을 고른다.
3. 추가·삭제·검사·토글 식을 먼저 적는다.
4. 전체 마스크와 종료 조건을 만든다.
5. 0번째 비트와 가장 높은 비트를 시험한다.

## 6. 자주 틀리는 지점

- `1 << x`가 int에서 overflow하므로 큰 비트에는 `1ULL << x`가 필요하다.
- 삭제를 XOR로 구현해 없던 원소를 오히려 추가하는 실수.
- `&`와 `==`의 우선순위를 믿고 괄호를 생략하는 실수.
- 논리 연산 `&&`와 비트 연산 `&`를 혼동하는 실수.
