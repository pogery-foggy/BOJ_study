# Bitset 기억 복원

## 한 문장 기억

여러 개의 참/거짓 상태를 64개씩 한 정수에 눌러 담아, 한 번의 비트 연산으로 64개의 상태를 동시에 갱신한다.

## 언제 꺼내는가

- 값의 범위는 크지만 상태가 `있다/없다`뿐일 때
- 같은 마스크끼리 `&`, `|`, `^`, 이동을 대량으로 수행할 때
- 문자열 DP를 행 전체가 아니라 "값이 증가하는 경계" 비트로 압축할 때

## 핵심 상태/불변식

- 값 `x`는 `block[x >> 6]`의 `(x & 63)`번째 비트에 있다.
- 블록은 반드시 0으로 초기화한다.
- 여러 블록을 왼쪽으로 밀 때는 높은 블록부터 처리해야 아직 읽지 않은 carry를 망가뜨리지 않는다.
- 비트셋 LCS에서는 비트 하나가 DP 값 자체가 아니라 LCS 값이 증가하는 열의 경계를 뜻한다.

## 내 코드 스타일 C++ 최소 구현 골격

스타일 근거: [13701.cpp](13701.cpp)의 전역 `bitset`과 입력값 `x`, 비어 있는 `init()` 뒤 `solve()`에서 입력이 끝날 때까지 처리하는 구조를 그대로 축약했다.

```cpp
#include <iostream>
#include <bitset>
using namespace std;

bitset<1 << 25> arr;
int x;

void init() {}

void solve() {
    while(cin >> x){
        if(arr[x]) continue;
        arr.set(x);
        cout << x << " ";
    }
}
```

직접 비트 블록을 관리해야 하는 문제와 달리, 이 골격은 값의 범위가 고정되어 있을 때 `bitset` 자체의 `[]`와 `set()`을 쓰는 사용자 풀이 방식이다.

## 빈 화면 구현 순서

1. 필요한 최대 비트 번호와 블록 수 `(N + 63) / 64`를 계산한다.
2. `test`, `set`, `count`부터 만든다.
3. 문제가 요구할 때만 블록별 `& | ^ - shift`를 추가한다.
4. 마지막 블록의 사용하지 않는 상위 비트를 마스킹한다.
5. 작은 정수를 직접 이진수로 적어 연산 결과를 확인한다.

## 자주 틀리는 지점

- `1 << k`는 `k >= 31`에서 위험하므로 `1ULL << k`를 쓴다.
- 다중 블록 뺄셈은 하위 블록에서 상위 블록으로 borrow를 전달한다.
- shift 중 `block[i + 1]`가 배열 끝을 넘지 않게 여분 블록 또는 경계 검사가 필요하다.
- 고정 크기 `bitset`은 입력 상한보다 작으면 조용히 잘못된 답을 만든다.
