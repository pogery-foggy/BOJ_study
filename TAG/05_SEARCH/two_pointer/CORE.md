# 투 포인터 핵심

## 1. 한 문장 기억

두 경계가 한 방향으로만 움직이게 만들어, 다시 볼 필요 없는 구간을 매 단계 버린다.

## 2. 언제 꺼내는가

- 정렬된 배열에서 합이 목표인 두 수를 찾는다.
- 양수 배열의 연속 부분합처럼 오른쪽을 늘리면 값이 커지고 왼쪽을 줄이면 작아진다.
- 고정 길이 구간을 한 칸씩 미는 슬라이딩 윈도우가 필요하다.

## 3. 핵심 상태 / 불변식

- 정렬 합 탐색: 아직 가능한 쌍은 `[left, right]` 안에만 있다.
- 연속합: `sum`은 정확히 현재 반열린 구간 `[left, right)`의 합이다.
- 매 반복에서 적어도 한 포인터가 전진하므로 전체 O(N)이다.

## 내 코드 스타일 C++ 최소 구현 골격

스타일 근거: [3273.cpp](./3273.cpp)의 전역 `vector<int> arr`, `back`/`top` 포인터명, `init()`에서 정렬과 경계 설정, `solve()`의 단일 `while` 구조를 축약했다.

```cpp
vector<int> arr;
int x, N, back, top, answer;

void init() {
    cin >> N;
    arr.resize(N);
    for (auto &a : arr)
        cin >> a;
    cin >> x;
    sort(arr.begin(), arr.end());
    back = 0;
    top = arr.size() - 1;
}

void solve() {
    while (back < top) {
        if (arr[back] + arr[top] == x) {
            answer++;
            top--;
            back++;
        } else if (arr[back] + arr[top] > x)
            top--;
        else
            back++;
    }
    cout << answer;
}
```

연속 부분합에서는 [2003.cpp](./2003.cpp)처럼 `pre`, `suf`, `cur`를 전역으로 둘 수 있다. 다만 원본은 `suf++` 뒤 `arr[suf]`를 더할 때 끝을 넘을 수 있으므로, 다시 구현할 때는 증가 직후 `suf == N` 검사를 먼저 한다.

## 5. 빈 화면 구현 순서

1. 정렬형인지 연속 구간형인지 구분한다.
2. 포인터가 가리키는 구간을 `[l,r]` 또는 `[l,r)` 중 하나로 선언한다.
3. 그 정의에 맞춰 `sum` 초기값을 잡는다.
4. 값이 작을 때와 클 때 어느 포인터를 움직일지 쓴다.
5. 배열 접근 전에 끝 경계를 검사한다.
6. 길이 1, 답 없음, 마지막 원소에서 답이 나는 경우를 확인한다.

## 6. 자주 틀리는 지점

- `right++` 후 `a[right]`를 읽어 배열 끝을 넘는 실수.
- 음수가 섞인 연속합에 양수용 투 포인터를 그대로 쓰는 실수.
- 원형 고정 창에서 `N==M`인 같은 창을 N번 세는 실수.
- 중복 원소가 허용되는 두 수 문제에서 같은 인덱스를 두 번 쓰는 실수.
